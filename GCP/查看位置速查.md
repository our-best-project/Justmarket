## 📍 五個地方，各放什麼

### 1. Cloud Run — 執行中的服務

<https://console.cloud.google.com/run?project=eventsignal-nash-2026>

看得到：網址、目前版本（revision）、CPU/記憶體設定、環境變數、請求量圖表。

```powershell
gcloud run services list --region=asia-southeast1          # 列出所有服務
gcloud run services describe eventsignal-api --region=asia-southeast1   # 完整設定
gcloud run revisions list --service=eventsignal-api --region=asia-southeast1  # 版本歷史
```

> **環境變數（含明文 `DATABASE_URL`）就在這裡**：服務詳情頁 →
> 「修訂版本」分頁 → 展開 →「變數與密鑰」。任何有專案讀取權限的人都看得到。

### 2. Artifact Registry — 容器映像檔

<https://console.cloud.google.com/artifacts?project=eventsignal-nash-2026>

路徑 `asia-southeast1-docker.pkg.dev/eventsignal-nash-2026/eventsignal/api`

裡面是 `pyproject.toml` 的 `api` extra 裝好的套件 + `backend/` 與 `spider_forge/`。

```powershell
gcloud artifacts docker images list asia-southeast1-docker.pkg.dev/eventsignal-nash-2026/eventsignal
```

### 3. Cloud Build — 建置紀錄

<https://console.cloud.google.com/cloud-build/builds?project=eventsignal-nash-2026>


bucket 名稱 `eventsignal-nash-2026_cloudbuild`，路徑 `source/`。
每次部署上傳的那包 7.2 MB build context 存檔（**不會被執行**，只是建置材料）。


# 🎤 現場展示 SOP

> 最容易出包的兩件事：**冷啟動**（服務睡著，第一個請求要等幾秒）
> 和 **Neon 沒資料**（服務正常但端點回空陣列）。兩個都能事前排除。

## 前一天：確認 Neon 真的有資料

**最容易被忽略、也最尷尬的失敗。** 服務活得好好的，但 `/api/v1/events`
回空陣列——因為資料管線還在本機跑，線上 API 只會回 Neon 裡「上次跑管線」的內容。

```powershell
Invoke-RestMethod https://eventsignal-api-894746398367.asia-southeast1.run.app/api/v1/events
```

- 有東西 → 安心
- 空的 → 先在本機跑一次 Prefect 管線，資料進 Neon 後線上立刻就看得到

順手也確認一下健康狀態：

```powershell
Invoke-RestMethod https://eventsignal-api-894746398367.asia-southeast1.run.app/health
```

## 展示前 10 分鐘：開展示模式

```powershell
cd C:\final_project_version\Stock-information-platform\workspace\GCP
.\demo-mode.ps1 -On
```

把 `min-instances` 設成 1，服務常駐待命，**冷啟動歸零**。
腳本會自動打一次 `/health` 暖機並印出回應時間。

## 展示：開 `/docs`

```
https://eventsignal-api-894746398367.asia-southeast1.run.app/docs
```

`/docs` 是最好的展示面——FastAPI 自動生成的互動介面，可以當場
按「Try it out」→「Execute」，即時秀出真實 JSON 回應。比投影片有說服力。

**先加到瀏覽器書籤。** 網址很長，台上手打一定出錯。

建議的展示順序：

1. `/health` → 證明服務活著、資料庫也通
2. `/docs` → 展示完整 API 契約（5 個端點一目了然）
3. `/api/v1/events` 按 Execute → 秀出真實資料

## 展示結束：關掉

```powershell
.\demo-mode.ps1 -Off
```

改回 `min-instances=0`，恢復閒置不計費。
**別忘記這步**——常駐狀態會一直計費。

隨時查目前狀態：

```powershell
.\demo-mode.ps1 -Status
```

## 找不到東西時的三個檢查點

1. **專案選錯了。** Console 左上角的專案選擇器要是 `eventsignal-nash-2026`。
   你帳號下有 8 個專案，很容易看到別的專案的空畫面。
2. **區域選錯了。** Cloud Run 頁面預設可能顯示別的區域，要選 `asia-southeast1`。
3. **指令沒帶 `--region`。** gcloud 沒指定區域時可能查不到，一律加
   `--region=asia-southeast1`。
