# crawler_legacy — 舊版抓取工具

> **不是正式入口。** 正式新聞入口是 `crawler/`（Scrapy），由 `../ingestion.py` 呼叫，
> 排在 Prefect flow 裡。本目錄不在任何排程內。

留著的唯一理由：`base.py` 的 `related_tickers` 標註邏輯還在被
`scripts/seed_articles.py` 使用（把凍結語料灌進 `articles` 表時要標個股）。
那套邏輯是實測調出來的，見下。等 seed 流程改走 `ingestion.py`，整個目錄就該刪掉。

## base.py — related_tickers 標註

規格原本一句「用公司名↔代號對照表標」把這題講得像查表。實測不是：拿 `tickers` 表
2,709 個公司名 naive 匹配 5,409 篇新聞 → 9.9% 的新聞命中超過 6 家、單篇最多 58 家。
這是 NER 問題，不是查表。

### 只掃標題，不掃內文

`related_tickers` 的語意是「這個事件**關於**誰」，不是「內文**提到**誰」。實測 4,486 篇：

| | 標題+內文 | **只用標題** |
|---|---|---|
| 有標到 | 91.2% | 66.3% |
| 恰好 1 家 | 39.0% | **58.0%** |
| >4 家（雜訊） | 13.3% | **0.1%** |
| 單篇最多 | **58 家** | **5 家** |

用 25pp 涵蓋率換掉 99% 雜訊。掃內文的實際後果是：查台積電會回傳「聯發科」
「金融業防詐」「國銀擴張海外」這些只是內文提到台積電的新聞。

### 三層策略

| | 條件 | 精確度 |
|---|---|---|
| Layer 1 | 標題明寫代號「(2330)」且該代號存在 | 最高 |
| Layer 2 | 標題命中公司名，且該名通過三道濾網 | 次之 |
| Layer 3 | 其餘 → `[]` | 合法空值，不猜 |

Layer 2 的三道濾網，每道都是實測結論：

1. **最長匹配**：長名先掃、掃到就挖掉。否則「中鋼構」會同時命中「中鋼」。
2. **停用清單**（`data/ticker_stoplist.json`）：名字剛好是常用詞的公司 ——
   大陸(2526)、聯合(4129)、卓越(2496)、全台(3038)。判別式是代號共現率：
   真公司偶爾會被寫成「群聯(8299)」，常用詞不會。清單由
   `scripts/build_ticker_stoplist.py` 產出，資料驅動，勿手改。
3. **同名歧義**：5 個名字對到 2 個代號（神達→2315/3706、永信→1716/3705 等，
   全是「舊公司 + 控股公司」同名）。名稱層無法判斷，一律排除，只靠 Layer 1。

## 資料界線

媒體來源只存標題＋導言／摘要＋發佈時間＋原始連結，**不轉存全文**；官方公告（MOPS
重大訊息）可存全文。不爬 PTT／Dcard，不碰付費國際媒體。
